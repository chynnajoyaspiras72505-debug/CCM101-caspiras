# Mission Reflection

Automation is critical when managing hundreds of cloud servers because handling each server manually would take a lot of time and could lead to human errors. Scripts and scheduled tasks can perform repetitive operations consistently, such as creating backups, which allows cloud administrators to manage many systems more efficiently. However, automation can also be dangerous when a script contains a destructive mistake. If a wrong command is scheduled to run on 1,000 servers, the same mistake could affect all of those systems very quickly. This is why scripts should be tested carefully and reviewed before they are deployed or scheduled. Writing a Bash script was also different from creating a Docker Compose YAML file in Mission 6. The Bash script contains commands that are executed by the shell and uses variables, file permissions, and backup operations, while Docker Compose uses YAML configuration to define and manage application services and containers. Looking back at my GitHub repository from Laboratory 1 to Laboratory 9, my understanding of Cloud Computing has developed from learning basic cloud concepts to performing practical tasks involving infrastructure, applications, data, deployment, security, and automation. Each laboratory introduced a different responsibility and helped me understand how the different parts of cloud computing work together. The role I enjoyed the most was the Cloud Security Engineer because it showed me how important it is to protect cloud resources and control access. Learning about firewalls, open ports, and security practices helped me understand how cloud systems can be protected from possible threats. Overall, this mission showed me that automation is useful for managing cloud environments efficiently, but it must always be planned, tested, and reviewed carefully.
